Major Project Specification Deep Dive

Cyber-Physical Smart Farming System • Final Year Engineering Project

Project Title

"An Intelligent IoT-Driven Smart Farming Using Digital Twin for Groundnut Disease Prediction and Blockchain for Data Transparency"

1. Problem Statement

Groundnut (Arachis hypogaea) is a vital global commercial oilseed and food crop. However, farmers face critical vulnerabilities that compromise yields:

  • Manual Crop Scouting: Identifying fungal pathogens by eye is slow, subjective, and usually happens only after severe irreversible damage.
  • Microclimatic Stress: Sudden relative humidity spikes and soil moisture deficits accelerate fungal spore proliferation before symptoms appear.
  • Data Silos: Traditional farms lack unified representations connecting live edge telemetry with pathology diagnosis.
  • Trust & Transparency Deficit: Without immutable records, verifying crop authenticity for organic certification and crop insurance claims is difficult.

2. Project Objectives

  • Implement continuous multi-sensor environmental telemetry using an ESP32 microcontroller node.
  • Develop an automated foliar disease classifier distinguishing Healthy, Rust (Puccinia arachidis), Early Leaf Spot, Late Leaf Spot, and Leaf Spot Complex using a hybrid Vision Transformer (ViT) and XGBoost approach.
  • Build a virtual Digital Twin that calculates an explainable, deterministic 0–100 Farm Health Score.
  • Integrate a SHA-256 cryptographic blockchain audit ledger to store tamper-evident sensor and prediction records.
  • Deliver a centralized, responsive web dashboard with real-time Chart.js telemetry charts and printable audit reports.

3. Proposed Solution

The system bridges the physical farm and digital intelligence through a five-stage cyber-physical pipeline:

ESP32 Multi-Sensors ➔ Flask REST API (HTTP) ➔ ViT + XGBoost Pathology Classifier ➔ Agronomic Digital Twin (0–100 Vitality Score) ➔ Cryptographic SHA-256 Blockchain Ledger ➔ Farmer Web Dashboard

6. AI Foliar Disease Diagnosis Pipeline

The vision system classifies groundnut foliar pathogens using a hybrid Vision Transformer (ViT) and XGBoost architecture:

  • Image Tokenization: Standardized 224×224 input images are divided into 196 non-overlapping 16×16 patches projected to 192-dimensional latent embedding tokens with positional encodings.
  • Transformer Encoder: Passed through 6 Transformer blocks with 4-head self-attention to capture long-range leaf lesion patterns.
  • Agronomic Domain Features: Extracted features are combined with 11 domain spectral/texture indices (Excess Green Index, Rust Necrosis Ratio, Yellow Chlorotic Halo Index).
  • XGBoost Classification: Multi-class gradient boosted decision trees predict probabilities across 5 target states: Healthy, Rust (Puccinia arachidis), Early Leaf Spot (Cercospora arachidicola), Late Leaf Spot (Cercosporidium personatum), and Leaf Spot Complex.
  • Severity Assessment & Advice: High / Medium / Low severity scoring paired with actionable agronomic treatments (e.g. Chlorothalonil / Mancozeb dosage).

7. Digital Twin Farm Health Scoring Engine

The Digital Twin computes an explainable, deterministic Farm Health Score (0–100) by evaluating real-time sensors against optimal groundnut agronomy parameters:

Parameter Max Points Optimal Agronomic Target
Soil Moisture 25 pts 65% – 80% root-zone moisture (prevents pod rot or wilting)
Temperature 20 pts 26°C – 30°C optimal groundnut vegetative/flowering range
Pathology Health 20 pts Healthy = 20 pts (Low severity = 12 pts, Medium = 6 pts, High = 0 pts)
Relative Humidity 15 pts 55% – 70% relative humidity
Soil pH 15 pts 6.0 – 6.8 pH for sandy loam nutrient uptake
Rain Presence 5 pts Dry foliage (minimizes fungal spore germination)
Status Bands: 90–100 = GOOD (Optimal) | 60–89 = MODERATE (Warning) | 0–59 = AT RISK (Hazard)

8. SHA-256 Cryptographic Blockchain Audit Ledger

To eliminate data tampering in farm audit logs and crop insurance claims, all telemetry cycles and disease predictions are permanently sealed into an educational Python SHA-256 blockchain:

Genesis Block #0

Initialized with previous hash set to 0000000000000000 and verifiable timestamp root.

SHA-256 Hashing

Each block encapsulates index + timestamp + payload + previous_hash + nonce, generating a unique 64-character hex hash.

Tamper Verification

The backend includes an integrity verification API endpoint (/api/blockchain/verify) that recalculates consecutive hashes to detect any database tampering.

Audit Traceability

Allows agricultural inspectors and crop insurers to independently inspect unalterable farm conditions.

Block Structure (SQLite Table: blockchain_records)

• block_index: INTEGER (Sequential Block Number)
• timestamp: TEXT (ISO 8601 UTC Time)
• data: TEXT (JSON Payload: Sensor Telemetry or AI Diagnosis)
• previous_hash: TEXT (SHA-256 Hash of Preceding Block)
• current_hash: TEXT (SHA-256 Hash of Current Block)
